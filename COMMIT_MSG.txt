Fix the reminder workflow: GITHUB_TOKEN must be passed explicitly

GITHUB_TOKEN is exposed to a workflow as the `secrets` context, not as an
inherited environment variable, so publish-reminder-issue.mjs found no token and
the first run failed at the publishing step. The step now passes it as GH_TOKEN.

The error message no longer claims a token should already be present; it prints
the exact `env:` snippet and the `permissions: issues: write` requirement.

Also bumps the actions to their current majors (checkout v5, setup-node v6,
configure-pages v6, upload-pages-artifact v5, deploy-pages v5) and the runner
Node to 24, which clears the Node 20 deprecation warnings.
